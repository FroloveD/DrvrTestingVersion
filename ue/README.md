# UEDev — начало работы

**Статус:** исходный C++-каркас под **Unreal Engine 5.7**, клавиатура и мышь.
Предыдущая версия каркаса собрана и запущена пользователем на UE 5.7.4/Windows 11: газ, тормоз, камера и пауза работают. **Текущее обновление динамики ещё требует UE-пересборки и проверки на ПК пользователя.**
В среде агента нет UE SDK; проверяются независимый C++ и численное совпадение продольных функций с TS. Это не готовый порт и не доказательство прироста FPS.

Веб-версия остаётся в корне репозитория без изменений поведения. Отдельный проект: `ue/UEDev/UEDev.uproject`.
План и критерии: [PLAN.md](PLAN.md).

## 1. Установка на компьютере разработчика (Windows)

1. Установить Unreal Engine **5.7** через Epic Games Launcher. Версия выбрана как базовая для прототипа, не как заявление о последней версии UE.
2. Установить Visual Studio 2022 с workload **Game development with C++**, MSVC и Windows SDK, совместимыми с выбранной UE 5.7. Сверить компоненты с подсказками установщика Epic/UE.
3. Открыть `ue/UEDev/UEDev.uproject`. При запросе пересборки согласиться.
4. Если автоматическая сборка не удалась: ПКМ по `.uproject` → **Generate Visual Studio project files**, открыть `UEDev.sln`, выбрать **Development Editor / Win64**, собрать цель **UEDevEditor**. Не включать Live Coding для первой сборки.
5. Если UE не привязана к `.uproject`, открыть проект через Launcher/Unreal Editor, а не менять версию проекта наугад.

Альтернатива из PowerShell (исправить путь к установленному движку):

```powershell
$UE = 'C:\Program Files\Epic Games\UE_5.7'
$Project = (Resolve-Path '.\ue\UEDev\UEDev.uproject').Path
& "$UE\Engine\Build\BatchFiles\Build.bat" UEDevEditor Win64 Development "-Project=$Project" -WaitMutex
if ($LASTEXITCODE -ne 0) { throw 'Сборка UEDevEditor не прошла' }
& "$UE\Engine\Binaries\Win64\UnrealEditor.exe" $Project
```

Команды запускаются из корня репозитория. Linux/macOS также требуют установленного UE и платформенного toolchain; инструкции выше предназначены для Windows, их нельзя выполнять там буквально.

## 2. Первый запуск в редакторе

1. Открывается `/Engine/Maps/Entry`. **Не сохранять изменения в engine-карте.**
2. Нажать **Play → Selected Viewport** и кликнуть по игровому окну для фокуса.
3. Сначала появляется **стартовый экран UEDev**: заезд, маршруты, автомобиль, настройки, журнал. Доступны выбор двух тестовых маршрутов, настройка газа и последние итоги текущей сессии. Полный редактор маршрутов, OSM, экзаменационная оценка и реплей ещё не перенесены.
4. Нажать **«Начать выбранный заезд»**: меню скрывается, начинается холодный заезд.
5. GameMode `UEDevGameMode` задан в `Config/DefaultEngine.ini`: он создаёт плоскость 120×80 м, стены, ориентиры и направленный свет. Ручная сборка карты и скачивание ассетов не нужны.
6. Появляется машина-прямоугольник и текстовая инструкция. Это технический placeholder, не финальная модель Ceed.
7. Удерживая **S**, нажать **Enter**, отпустить S, затем **W**. **Esc** в игре — пауза; из неё можно продолжить, начать заново, завершить и увидеть технический итог или вернуться в меню без сохранения. В PIE редактор может перехватывать Esc для Stop: для проверки игрового Esc запускать **Play → Standalone Game**, либо изменить привязку Stop Play Session в редакторе. Для освобождения курсора PIE — **Shift+F1**.

Если площадка/машина не появились, проверить **Output Log**, сборку модуля и **World Settings → GameMode Override** (None либо UEDevGameMode). Для собственной карты впоследствии сохранить новый уровень в `/Game/Maps`, а не поверх Entry.

## 3. Управление прототипом

| Клавиша/жест | Действие |
|---|---|
| Enter | Подготовка без сброса: на месте в P/N/D включает ДВС, выбирает D, снимает ручник, пристёгивает ремень. Из P — только с S; на ходу/R/M ничего не меняет |
| ← / → | Взгляд влево/вправо в салоне; удерживать, 2 — взгляд вперёд. ↑/↓ остаются коробкой |
| C / 1 / 2 | Смена камеры / сзади / салон с возвратом взгляда вперёд |
| H | Скрыть/показать приборные панели HUD; управление не меняется |
| L | Фары вкл/выкл независимо от ДВС и Enter |
| Backspace | Холодный сброс: P, двигатель выключен, ручник затянут, ремень снят |
| I / Space / B | Двигатель / ручник / ремень |
| W / S | Плавный газ до 60 % / рабочий тормоз (никогда не реверс) |
| Shift+W в D/M | Быстрый полный газ |
| A / D | Руль влево / вправо; при отпускании — самовозврат |
| P / R / N / F | Выбор P / R / N / D с блокировками |
| ↑ / ↓ | По селектору P–R–N–D |
| Shift+↑ / Shift+↓ | D→M на текущей ступени, затем ручные ступени вверх/вниз с защитой от перекрута |
| ЛКМ + движение мыши | Руль: вправо — поворот вправо; удержание сохраняет угол |
| ПКМ + движение мыши | Орбита камеры |
| Колесо мыши | Приближение/удаление камеры |
| Ctrl + колесо | Уровень обычного газа 10–60 %, шаг 5 %; при этом зум не меняется |

Ручной холодный запуск: **I → удерживать S → F → отпустить S → Space → B → W**.
Из/в P нужен тормоз и запущенный ДВС; N↔D/R без тормоза при безопасной скорости. На ходу смена направления блокируется.

## 4. Что готово, а что ещё нет

Есть исходники: фиксированный шаг 1/60 с, плоская кинематика, продольная модель Ceed (тяга по ступеням, момент/RPM, пауза тяги при переключении, D1–D6 с адаптивными порогами, M, торможение двигателем, гидравлика тормоза, самоход D1), управление, ограничения селектора, sweep корпуса, внешняя камера, площадка и HUD. Источник геометрических/контрольных констант — `src/sim/vehicle.ts` и `src/sim/controls.ts`.

**Это пока не перенос всего симулятора один-в-один:** продольные функции перенесены из `src/sim/vehicle.ts`, но нет подвески, сцепления/бокового скольжения шин, кренов, рельефа, точного TS-реплея, оценки, журнала, импорта OSM, салона, зеркал, аудио, переназначения клавиш, упаковки релиза. M1–M6 теперь имеют разные тяговые характеристики и ограничения оборотов. Автомобиль не использует Chaos Vehicles и движется по плоскости без гравитации. Sweep не гарантирует непрерывную проверку вращения корпуса. Ограничение накопления кадра 0,25 с намеренно замедляет модель при зависании.

Руль/педали, Force Feedback, VR и несколько экранов **отложены**. Сравнение FPS до сопоставимого прототипа преждевременно.

## 5. Проверки

Независимая модель, Linux/macOS с g++ или совместимым clang++:

```sh
g++ -std=c++17 -Wall -Wextra -Werror -pedantic \
  -I ue/UEDev/Source/UEDev/Public \
  ue/UEDev/Tests/DrivingModelTest.cpp -o /tmp/uedev-model-test
/tmp/uedev-model-test
```

Эту проверку выполняет отдельный workflow `UEDev portable core (not Unreal build)`; он **не проверяет UHT, UE API, редактор или упаковку**.

После реальной UE-сборки пройти руками и записать версию UE/ОС и результат:

- [ ] Play создаёт площадку, машину, свет и читаемый HUD; в Output Log нет ошибок проекта.
- [ ] Холодный старт не двигается; S+Enter подготавливает без сброса; Backspace возвращает холодное состояние.
- [ ] Газ 60 %, Shift в D/M даёт 100 %, отпускание Shift возвращает 60 %.
- [ ] S останавливает без реверса; в N газ не разгоняет, остаётся естественный выбег.
- [ ] P/R и смена направления на скорости блокируются; N↔D не требует тормоза.
- [ ] A/D и ЛКМ поворачивают ожидаемо; ПКМ вращает камеру, колесо меняет дистанцию.
- [ ] Корпус останавливается у стены; после смены фокуса W/S не залипают.
- [ ] Stop/Play не создаёт дубликаты площадки.

Если сборка упала, прислать **первую ошибку** из Build Output или `Saved/Logs/UEDev.log`, а не только итог «build failed». Этот лог локальный, его не нужно коммитить.

## 6. Меню и жизненный цикл заезда

`SessionFlow.h` задаёт разрешённые состояния Menu → Driving ↔ Paused → Summary. `UEDevPlayerController` строит Slate-интерфейс без UMG/Blueprint-ассетов и управляет вводом. Это отдельные экраны **в одном мире**, не загрузка новой карты: площадка создаётся один раз, повторные заезды её не дублируют. Настоящий loading screen понадобится при асинхронной загрузке маршрутов/ассетов; сейчас искусственной задержки/полосы прогресса нет.

В меню машина скрыта, её Tick и Input отключены. В паузе и итоге модель также не тикает; отключение относится к машине, не является глобальной паузой всех будущих акторов мира. При смене режима сбрасываются удерживаемые клавиши. Во время вождения нет верхнего меню: только скорость/состояние машины, краткая подсказка и дисклеймер. Настройки и выбор маршрута остаются на стартовом экране. Уровень газа регулируется слайдером; полный редактор маршрутов ещё не перенесён.

Дополнительный ручной smoke **в Standalone Game**:
- [ ] При запуске меню полноэкранное и непрозрачное; курсор виден. W/S/Enter не запускают скрытую машину.
- [ ] Разделы меню кликабельны, Tab/Enter позволяют активировать кнопки; недоступные функции честно описаны.
- [ ] «Начать заезд» скрывает меню, возвращает захват мыши и создаёт холодное состояние.
- [ ] Esc открывает паузу. Позиция/скорость не меняются во время ожидания и нажатия W/S.
- [ ] Esc/«Продолжить» возвращает тот же заезд; мышь снова управляет камерой/рулём, а не кнопками.
- [ ] «Начать заново» даёт холодный старт без дублирования стен/площадки.
- [ ] «Завершить» показывает технический итог, не фиктивную экзаменационную оценку.
- [ ] «На стартовый экран» и «Новый заезд» работают; после десяти циклов нет наложенных меню или залипшего ввода.
- [ ] Stop/Play удаляет старый Slate-экран, не оставляя его в viewport.

Архив с текущими исходниками можно воспроизвести из корня репозитория:
```sh
python3 tools/package-uedev.py
```
Архив — исходники для сборки, не EXE. UE API/Slate и эти переходы ещё требуют проверки в настоящем редакторе.

## Совместимость UE 5.7: первые ошибки сборки

Обе цели `Source/UEDev.Target.cs` и `Source/UEDevEditor.Target.cs` используют `BuildSettingsVersion.V6` по диагностике установленной UE 5.7.4. Это не подтверждение успешной сборки модуля: следующие ошибки следует разбирать по UBT Log.txt. `TargetBuildEnvironment.Unique` для Launcher-установки не включать.

Если UBT сообщает `0xFF is an invalid start of a value`, descriptor повреждён/в неверной кодировке. Заменить `UEDev.uproject` из свежего архива целиком. В архиве он записан ASCII-совместимым UTF-8 без BOM (Unicode в JSON экранирован); не сохранять его как UTF-16. После замены повторное переключение версии не нужно — EngineAssociation уже 5.7.

## 7. Обновление продольной динамики

Обычная клавиатура не измеряет давление: W плавно набирает команду до выбранного уровня. **Ctrl+колесо** задаёт 10–60 %, **Shift+W в D/M** даёт быстрые 100 %. Отпускание газа снимает команду, заслонка закрывается отдельно; Shift без W не держит газ. В HUD видны D1–D6/M1–M6, RPM, фактическая заслонка и давление тормоза. Лимит обычного газа сохраняется между сбросами, а через кнопку сохранения или Ctrl+колесо — и на диск (раздел 8).

Переносимые тесты: разгон 0–100 на свободной прямой без UE-стен — **30,50 с обычным газом 60 %**, **10,70 с Shift**; несколько реальных переключений, спад RPM, M-ограничитель/защита, N без связи с мотором, плавный тормоз и регулировка газа. Это расчёт модели, не замер UE. Короткой площадки для 0–100 недостаточно; для проверки выбирайте километровую прямую из меню.

В полном репозитории после `npm ci` можно выполнить:
```sh
node tests/uedev-powertrain-parity.mjs
```
Тест сверяет 2656 значений C++/TS (тяга, RPM, сопротивление, тормоз и самоход) с абсолютным допуском 1e-9. Это не доказательство полного совпадения симуляции или кроссплатформенной побитовой детерминированности.

После пересборки проверить: 20 % против 60 % газа, более поздние переключения под Shift, падение RPM после повышения, удержание M на скорости, выбег N и отпускание/повторное нажатие S. Оба тестовых маршрута ограничены стенами; для полного разгона выбирайте длинную прямую.

## 8. Рабочее стартовое меню и маршрут

На стартовом экране выберите **Маршруты**:
- **Площадка 120×80 м**: две контрольные точки, в последней нужна остановка.
- **Тестовая прямая 1 км**: старт z=−500 м, КТ z=−250/0/250/500 м, остановка в конце; стены стоят за финишем. Это технический стенд динамики, не новое экзаменационное упражнение.

Нажмите **Начать выбранный заезд**. Вождение остаётся без верхнего меню. КТ проходят только последовательно; быстрый проезд сквозь круг между двумя шагами тоже учитывается. Для последней КТ нужно находиться внутри круга со скоростью менее 0,15 м/с. Стойки обозначают ворота, зелёные/жёлтые debug-круги — область КТ (в Development). После всех КТ модель не блокируется; Esc → Завершить закрывает заезд отдельно.

HUD и итог показывают КТ, симуляционное время, расстояние и максимальную скорость до последней КТ (после прохождения счётчики фиксируются). Пауза не добавляет время. Backspace и «Начать заново» сбрасывают прогресс и ставят автомобиль на старт выбранного маршрута. Enter не меняет позицию, КТ, время, дистанцию или максимум скорости: это только подготовка к движению на месте.

**Настройки и управление**: слайдер обычного газа 10–60 %, «Сохранить настройки», сброс до 60 %. Уровень газа и выбранный маршрут сохраняются локально в секции `[UEDev]` файла `GameUserSettings.ini` (каталог платформы под Saved/Config либо пользовательский каталог в зависимости от режима запуска). Ctrl+колесо во время езды также сохраняет уровень. Слайдер применяется сразу; для записи на диск нажмите кнопку сохранения. При ошибках доступа к каталогу запись на диск не гарантирована.

**Журнал и разбор**: до десяти завершённых технических итогов в памяти текущего запуска, без ФИО и штрафов. После перезапуска программы история исчезнет. Это не перенос IndexedDB-журнала веба, не постоянное сохранение и не реплей.

Новые части Slate/Config/создания маршрутов требуют сборки UE на ПК пользователя. Переносимо проверены порядок КТ, пересечение за шаг, остановка, прогресс/сброс, метрики и нормализация настроек.

Дополнительная ручная проверка:
- [ ] Настроить 25 % газа, сохранить, закрыть/открыть игру — значение восстановилось.
- [ ] Выбрать прямую, начать — старт у начала длинной площадки, а не в её центре.
- [ ] Пройти КТ по порядку, остановиться в последней, завершить через Esc; итог появился в меню.
- [ ] Переключить площадку/прямую несколько раз — старые стены/ворота не остаются.
- [ ] В паузе счётчики не меняются; перезапуск обнуляет их, Enter сохраняет.
- [ ] При новом запуске история пуста, но газ и маршрут восстановлены.

### Визуальный слой UEDev: модели и свет

Вместо куба используется сборная low-poly модель: кузов, кабина, непрозрачные тёмные окна, четыре статичных колеса, бамперы и цветные вставки фар. Это условный автомобиль, не точная модель Kia и не салон. Детали сделаны из Engine/BasicShapes; цвет задаётся параметром Color динамических материалов. Единственная коллизия — прежний Body, физика не менялась. Фары пока не светят, колёса не анимированы.

Площадка получила тёмное покрытие, визуальную прерывистую ось и краевые полосы, конусы вместо кубических маркеров. Разметка — ориентир технической сцены, не утверждённая схема дорожного движения. Свет: один динамический солнечный источник, SkyAtmosphere и SkyLight; без внешних текстур, bake и Lumen. При смене маршрута свет не дублируется. Поведение не проверено в UE SDK.

Ручная проверка после пересборки UE: видны кузов/окна/колёса и разные цвета; колёса у поверхности; небо не чёрное, затенённая сторона читается; разметка не мерцает; после трёх смен маршрута нет остатков моделей; коллизии и управление прежние. Если используемый Engine-материал не имеет параметра Color, детали останутся стандартного цвета — проверить в UE 5.7.

### Исправление C1083: SkyAtmosphere (лог пользователя)

Пользовательские Log-2/Log-3 выявили неверные подключения `Engine/SkyAtmosphere.h` и `Atmosphere/SkyAtmosphere.h`. Обе версии заменены: теперь используется `Components/SkyAtmosphereComponent.h`, компонент создаётся на обычном AActor, регистрируется и становится его корнем. Старое исправление одной строки больше не применять — замените UEDevGameMode.cpp целиком. Переустановка UE/Visual Studio и удаление Saved не нужны. Полная UE-сборка после исправления ещё не подтверждена; проверка packager исключает возврат обоих ошибочных include, но не заменяет компилятор Unreal.

### Материалы и свет автомобиля (следующий шаг миграции)

По скриншоту пользователя подтверждён запуск сборки с USkyAtmosphereComponent, новым HUD и сборным автомобилем. Замечен шахматный материал. Теперь всем деталям машины, покрытию, полосам и конусам явно назначается Engine/BasicShapes/BasicShapeMaterial перед созданием динамического экземпляра, вместо материала по умолчанию из меша. Цвет задаётся параметром Color; результат нового назначения ещё нужно проверить на UE 5.7. Это не импорт PBR-ассетов.

Добавлены два передних прожектора, два красных стоп-сигнала и белый прожектор заднего хода. Политика прототипа: передний свет переключается L независимо от ДВС, задний ход при ДВС+R, стоп при давлении тормоза >2%, независимо от ДВС. Ручник не включает стопы. Источники без теней; настройки яркости предварительные, физическая фотометрия не откалибрована. Красная вставка сзади также меняет цвет; эмиссионного материала пока нет. Сброс немедленно выключает свет, Enter/I не меняют положение выключателя фар; в паузе состояние заморожено. Это не полный перенос наружного освещения веба: Q/E/Z пока не добавлены.

Проверить после замены **всей Source** и пересборки:
- [ ] Кузов синий, окна тёмные без шахматной сетки; покрытие тёмное, полосы светлые.
- [ ] L включает/выключает передний свет; Enter/I не переключают фары; Backspace выключает все источники.
- [ ] S включает красный свет сзади, после отпускания и спада давления он гаснет.
- [ ] При заведённом ДВС: S+R включает белый свет сзади; N выключает его.
- [ ] Обе карты, пауза/продолжение/повторный старт не оставляют лишние источники.
- [ ] Свет лучше виден с бокового/переднего ракурса (ПКМ), днём слабые пятна могут быть малозаметны.

Новые изменения материалов/источников здесь не компилировались Unreal SDK. Чистая логика включения покрыта C++-тестами; это не проверка внешнего вида.

### Исправление Enter / Backspace / L
- Backspace — единственный клавиатурный холодный сброс позиции, прогресса и счётчиков.
- Enter — подготовка без сброса: только при |v|≤0,35 м/с в P/N/D; из P нужен тормоз S. При отказе нет частичных изменений; в R/M и на ходу ничего не меняет. Повторное нажатие не обнуляет динамику.
- L — независимый выключатель передних фар, в том числе при заглушённом ДВС (аккумулятор пока не моделируется). Enter и I его не переключают; Backspace выключает.
- Ручной smoke: проехать часть маршрута, остановиться, записать КТ/время/дистанцию; нажать Enter — положение и прогресс прежние. На ходу Enter не меняет КПП. После Backspace — старт/нулевые счётчики/холодное состояние/фары выключены. Нажать L, затем I — фары остаются включены.

## HUD по логике Arena_v1

Логика группировки взята из `src/components/SimulatorView.tsx`, браузерный рендер не менялся:
- Слева внизу — крупная скорость (км/ч), тахополоса 0–6500 об/мин и подпись ДВС. Как в v1: зелёный до 4400, жёлтый от 4400, красный от 5500; в M1–M5 при 5500+ подсказка Shift+↑.
- Внизу по центру — селектор P/R/N/D с активной ступенью D1–D6/M1–M6, рядом состояния ДВС, ручника, ремня и фар с клавишами. Текст дублирует цвет, P не выдаётся за ручник.
- Справа внизу — отдельные шкалы газа (фактическая заслонка) и тормоза (давление), проценты и лимит обычного газа. Это не показания физических педалей.
- Сверху — текущая КТ, конкретное действие и дистанция до границы зоны **по прямой**, не навигационная длина дороги; справа — время/дистанция/максимум.
- Снизу — одна приоритетная подсказка: запуск → ремень → ручник → селектор → движение. Это информационная помощь, не штрафы и не принудительная блокировка.
- H скрывает/показывает панели, но не меняет управление/камеру. Учебный дисклеймер и H-подсказка остаются видны. В меню/паузе панели не рисуются, состояние видимости сохраняется в пределах текущего запуска.

Панели масштабируются под viewport от базовых 1280×720, закреплены по краям, с тёмной подложкой. Это первая информационная версия HUD: экранных кнопок, drag/resize, зеркал, карты, поворотников и экзаменационного счёта здесь ещё нет. Клавиши остаются прежними, Enter не сбрасывает заезд. На очень маленьком окне масштаб уменьшит и текст; для проверки используйте не менее 1280×720.

Ручной smoke нового HUD (Unreal SDK здесь отсутствует):
- [ ] 1280×720, 1920×1080 и 1024×768: нет перекрытий карточек/обрезания текста, центр дороги свободен.
- [ ] ДВС/ручник/ремень/L соответствуют машине, фары не зависят от Enter/I; H дважды не меняет машину.
- [ ] P/R/N/D/M и тахополоса соответствуют прежним диагностическим значениям; S/W плавно меняют соответствующие шкалы.
- [ ] До КТ убывает расстояние, в зоне 0; после последней КТ нет обращения к отсутствующей точке, текст предлагает Esc → Завершить.
- [ ] Backspace сбрасывает метрики, Enter сохраняет; пауза убирает приборы, продолжение возвращает; дисклеймер виден при H.
- [ ] Кириллица и размеры шрифта читаемы в вашей сборке UE 5.7; пришлите скриншот для корректировки.

## Вид из салона (первый прототип)

- **C** переключает внешний вид/салон, сохраняя настройки взгляда каждого вида.
- **1** — внешняя камера сзади (с сохранённой орбитой); **2** — место водителя и взгляд вперёд, FOV 85°.
- В салоне **ПКМ+мышь** поворачивает голову (yaw ±110°, pitch −40…30°), **колесо** меняет FOV 65–100°. Ctrl+колесо по-прежнему регулирует газ, а не камеру. ЛКМ остаётся рулением.
- Камера расположена слева по ходу движения: UE Y=−38 см, X=−30 см от центра кузова, высота 129 см над площадкой. Это предварительная посадка, не точная антропометрия Kia.
- Торпедо, консоль, двери/крыша/стойки и составной руль — встроенные примитивы. Руль визуально повторяет угол модели ±540°. Коллизия салона отключена, физика не меняется.
- Изнутри скрыты прежний сплошной блок кабины и непрозрачные панели «стёкол», вместо них — открытые проёмы. Снаружи прежняя оболочка возвращается, внутренние детали скрываются. Это не прозрачный PBR-салон и не лицензированная модель автомобиля.
- Переключение вида не сбрасывает позицию, КТ, время, газ или фары. Backspace сбрасывает руль/заезд, но оставляет выбранную камеру и взгляд. H независимо скрывает HUD; для обзора салона можно временно убрать приборы.
- Добавлены зеркальные окна и цифровые приборы на торпедо (см. ниже). Тела водителя и анимации колёс пока нет.

**Ручная проверка после полной пересборки (добавлены компоненты, не использовать только Live Coding):**
- [ ] Нажать 2 — видна дорога, торпедо и руль, нет сплошной стены перед глазами. 1 возвращает внешний вид; C переключает оба.
- [ ] ПКМ осматривает салон; 2 возвращает взгляд вперёд. При крайних углах нет критичного перекрытия/выхода камеры; если есть — прислать скриншот.
- [ ] A/D и ЛКМ поворачивают руль в соответствующую сторону, Backspace возвращает его в ноль.
- [ ] На ходу C/1/2 не меняют положение, скорость и КТ. Ctrl+колесо меняет только газ, обычное колесо — только активную камеру.
- [ ] Повторные переключения не оставляют непрозрачные стёкла внутри или исчезнувший кузов снаружи; пауза/меню/перезапуск сохраняют работоспособность.
- [ ] Проверить обзор с HUD и H при 1280×720 и 1920×1080. Новый салон/камера здесь не собирались Unreal SDK; source guards не заменяют эту проверку.

## Зеркала, приборы и стрелки головы

**F5/F6/F7** независимо включают/выключают заднее/левое/правое зеркало (в пределах запуска, без записи на диск); выключенное зеркало не захватывает кадры.

**Три зеркала** отображают реальную сцену через отдельные SceneCapture2D: центральное 320×96 и боковые 320×160. Как в v1, это накладные окна обзора, не текстуры на 3D-корпусах зеркал. Кадр отражён по горизонтали, подписи различают стороны. H скрывает телеметрию, но **не зеркала**. Они видны и с внешней камерой. Картинка обновляется не чаще 15 раз/с во время вождения; в паузе заморожена. Это предварительный бюджет, не результат замера производительности.

В captures скрыты блок кабины/непрозрачные окна, внутренние детали и текст приборов; кузов и колёса не скрываются целиком, чтобы сохранить возможные габаритные ориентиры. Зеркальные изображения не зависят от поворота головы и не захватывают HUD. Центральный ракурс чуть опущен к задней поверхности, боковые направлены назад/наружу. Углы ещё требуют проверки в UE: не считать их откалиброванным обзором реального автомобиля.

**Приборы на торпедо** — цифровой TextRender-дисплей скорости, текущей передачи D1–D6/M1–M6, оборотов, состояния ДВС, ручника и ремня. Данные те же, что в HUD; никакого вымышленного топлива/температуры или экзаменационных ламп. Это первый цифровой щиток, не точная приборная панель Kia и не стрелочные шкалы. Дисплей остаётся при H, виден только из салона.

**← / →** при удержании поворачивают голову в салоне со скоростью 85°/с, предел ±110°. Отпускание сохраняет направление; одновременное удержание отменяет поворот; **2** возвращает взгляд вперёд. ПКМ продолжает работать. **↑ / ↓** не управляют головой: они остаются селектором/ступенями, без двойных действий.

### Проверить руками в Unreal
- [ ] В зеркалах именно дорога позади: поставить машину перед известным конусом, проехать мимо и проверить стороны/горизонтальное отражение; задний ход приближает ориентир. Картинки не чёрные и не одинаковые.
- [ ] Поворот головы не поворачивает зеркальные камеры; C/1/2 и H не выключают зеркала. Пауза замораживает кадр, продолжение обновляет.
- [ ] В центральном окне нет сплошного блока кабины; проверьте тонкую заднюю поверхность как нижний ориентир. В боковых не должно быть сплошного кузова на весь кадр.
- [ ] ←/→ работают только в салоне и не меняют коробку; ↑/↓ не меняют взгляд. 2 центрирует. Одновременные ←/→ не вращают камеру.
- [ ] При H дисплей на торпедо остаётся; скорость/RPM/передача совпадают с HUD, кириллица читаема, руль не закрывает весь дисплей. Проверьте при взгляде чуть вниз ПКМ.
- [ ] После Backspace и нового заезда нет старых показаний; несколько смен маршрута не создают новые Capture-компоненты/RT.

Нужна **полная пересборка Source**: добавлены UPROPERTY/компоненты. Здесь нет UE SDK — новые SceneCapture/TextRender ещё не скомпилированы и не проверены визуально. Статические guards проверяют структуру исходников; C++-тесты — знаки/пределы/шаг стрелок. Это не замена ручному smoke зеркал и приборов.
