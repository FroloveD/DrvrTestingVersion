# UEDev — начало работы

**Статус:** исходный C++-каркас под **Unreal Engine 5.7**, клавиатура и мышь.
Предыдущая версия каркаса собрана и запущена пользователем на UE 5.7.4/Windows 11: газ, тормоз, камера и пауза работают. **Текущее обновление динамики ещё требует UE-пересборки и проверки на ПК пользователя.**
В среде агента нет UE SDK; проверяются независимый C++ и численное совпадение продольных функций с TS. Это не готовый порт и не доказательство прироста FPS.

Веб-версия остаётся в корне репозитория без изменений поведения. Отдельный проект: `ue/UEDev/UEDev.uproject`.
План и критерии: [PLAN.md](PLAN.md).

## 1. Установка на компьютере разработчика (Windows)

1. Установить Unreal Engine **5.7** через Epic Games Launcher. Версия выбрана как базовая для прототипа, не как заявление о последней версии UE.
2. Установить Visual Studio 2022 с workload **Game development with C++**, MSVC и Windows SDK, совместимыми с выбранной UE 5.7. Сверить компоненты с подсказками установщика Epic/UE.
3. Открыть `ue/UEDev/UEDev.uproject`. При запросе пересборки согласиться.
4. Если автоматическая сборка не удалась: ПКМ по `.uproject` → **Generate Visual Studio project files**, открыть `UEDev.sln`, выбрать **Development Editor / Win64**, собрать цель **UEDevEditor**. Не включать Live Coding для первой сборки.
5. Если UE не привязана к `.uproject`, открыть проект через Launcher/Unreal Editor, а не менять версию проекта наугад.

Альтернатива из PowerShell (исправить путь к установленному движку):

```powershell
$UE = 'C:\Program Files\Epic Games\UE_5.7'
$Project = (Resolve-Path '.\ue\UEDev\UEDev.uproject').Path
& "$UE\Engine\Build\BatchFiles\Build.bat" UEDevEditor Win64 Development "-Project=$Project" -WaitMutex
if ($LASTEXITCODE -ne 0) { throw 'Сборка UEDevEditor не прошла' }
& "$UE\Engine\Binaries\Win64\UnrealEditor.exe" $Project
```

Команды запускаются из корня репозитория. Linux/macOS также требуют установленного UE и платформенного toolchain; инструкции выше предназначены для Windows, их нельзя выполнять там буквально.

## 2. Первый запуск в редакторе

1. Открывается `/Engine/Maps/Entry`. **Не сохранять изменения в engine-карте.**
2. Нажать **Play → Selected Viewport** и кликнуть по игровому окну для фокуса.
3. Сначала появляется **стартовый экран UEDev**: заезд, маршруты, автомобиль, настройки, журнал. Редактор маршрутов и журнал пока отмечены как не перенесённые, это не работающие редакторы.
4. Нажать **«Начать заезд — тестовая площадка»**: меню скрывается, начинается холодный заезд.
5. GameMode `UEDevGameMode` задан в `Config/DefaultEngine.ini`: он создаёт плоскость 120×80 м, стены, ориентиры и направленный свет. Ручная сборка карты и скачивание ассетов не нужны.
6. Появляется машина-прямоугольник и текстовая инструкция. Это технический placeholder, не финальная модель Ceed.
7. Нажать **Enter**, затем **W**. **Esc** в игре — пауза; из неё можно продолжить, начать заново, завершить и увидеть технический итог или вернуться в меню без сохранения. В PIE редактор может перехватывать Esc для Stop: для проверки игрового Esc запускать **Play → Standalone Game**, либо изменить привязку Stop Play Session в редакторе. Для освобождения курсора PIE — **Shift+F1**.

Если площадка/машина не появились, проверить **Output Log**, сборку модуля и **World Settings → GameMode Override** (None либо UEDevGameMode). Для собственной карты впоследствии сохранить новый уровень в `/Game/Maps`, а не поверх Entry.

## 3. Управление прототипом

| Клавиша/жест | Действие |
|---|---|
| Enter | Быстрый старт: сброс в начало, ДВС включён, D, ручник снят, ремень пристёгнут |
| Backspace | Холодный сброс: P, двигатель выключен, ручник затянут, ремень снят |
| I / Space / B | Двигатель / ручник / ремень |
| W / S | Плавный газ до 60 % / рабочий тормоз (никогда не реверс) |
| Shift+W в D/M | Быстрый полный газ |
| A / D | Руль влево / вправо; при отпускании — самовозврат |
| P / R / N / F | Выбор P / R / N / D с блокировками |
| ↑ / ↓ | По селектору P–R–N–D |
| Shift+↑ / Shift+↓ | D→M на текущей ступени, затем ручные ступени вверх/вниз с защитой от перекрута |
| ЛКМ + движение мыши | Руль: вправо — поворот вправо; удержание сохраняет угол |
| ПКМ + движение мыши | Орбита камеры |
| Колесо мыши | Приближение/удаление камеры |
| Ctrl + колесо | Уровень обычного газа 10–60 %, шаг 5 %; при этом зум не меняется |

Ручной холодный запуск: **I → удерживать S → F → отпустить S → Space → B → W**.
Из/в P нужен тормоз и запущенный ДВС; N↔D/R без тормоза при безопасной скорости. На ходу смена направления блокируется.

## 4. Что готово, а что ещё нет

Есть исходники: фиксированный шаг 1/60 с, плоская кинематика, продольная модель Ceed (тяга по ступеням, момент/RPM, пауза тяги при переключении, D1–D6 с адаптивными порогами, M, торможение двигателем, гидравлика тормоза, самоход D1), управление, ограничения селектора, sweep корпуса, внешняя камера, площадка и HUD. Источник геометрических/контрольных констант — `src/sim/vehicle.ts` и `src/sim/controls.ts`.

**Это пока не перенос всего симулятора один-в-один:** продольные функции перенесены из `src/sim/vehicle.ts`, но нет подвески, сцепления/бокового скольжения шин, кренов, рельефа, точного TS-реплея, оценки, журнала, импорта OSM, салона, зеркал, аудио, переназначения клавиш, упаковки релиза. M1–M6 теперь имеют разные тяговые характеристики и ограничения оборотов. Автомобиль не использует Chaos Vehicles и движется по плоскости без гравитации. Sweep не гарантирует непрерывную проверку вращения корпуса. Ограничение накопления кадра 0,25 с намеренно замедляет модель при зависании.

Руль/педали, Force Feedback, VR и несколько экранов **отложены**. Сравнение FPS до сопоставимого прототипа преждевременно.

## 5. Проверки

Независимая модель, Linux/macOS с g++ или совместимым clang++:

```sh
g++ -std=c++17 -Wall -Wextra -Werror -pedantic \
  -I ue/UEDev/Source/UEDev/Public \
  ue/UEDev/Tests/DrivingModelTest.cpp -o /tmp/uedev-model-test
/tmp/uedev-model-test
```

Эту проверку выполняет отдельный workflow `UEDev portable core (not Unreal build)`; он **не проверяет UHT, UE API, редактор или упаковку**.

После реальной UE-сборки пройти руками и записать версию UE/ОС и результат:

- [ ] Play создаёт площадку, машину, свет и читаемый HUD; в Output Log нет ошибок проекта.
- [ ] Холодный старт не двигается; Enter включает готовый заезд; Backspace возвращает холодное состояние.
- [ ] Газ 60 %, Shift в D/M даёт 100 %, отпускание Shift возвращает 60 %.
- [ ] S останавливает без реверса; в N газ не разгоняет, остаётся естественный выбег.
- [ ] P/R и смена направления на скорости блокируются; N↔D не требует тормоза.
- [ ] A/D и ЛКМ поворачивают ожидаемо; ПКМ вращает камеру, колесо меняет дистанцию.
- [ ] Корпус останавливается у стены; после смены фокуса W/S не залипают.
- [ ] Stop/Play не создаёт дубликаты площадки.

Если сборка упала, прислать **первую ошибку** из Build Output или `Saved/Logs/UEDev.log`, а не только итог «build failed». Этот лог локальный, его не нужно коммитить.

## 6. Меню и жизненный цикл заезда

`SessionFlow.h` задаёт разрешённые состояния Menu → Driving ↔ Paused → Summary. `UEDevPlayerController` строит Slate-интерфейс без UMG/Blueprint-ассетов и управляет вводом. Это отдельные экраны **в одном мире**, не загрузка новой карты: площадка создаётся один раз, повторные заезды её не дублируют. Настоящий loading screen понадобится при асинхронной загрузке маршрутов/ассетов; сейчас искусственной задержки/полосы прогресса нет.

В меню машина скрыта, её Tick и Input отключены. В паузе и итоге модель также не тикает; отключение относится к машине, не является глобальной паузой всех будущих акторов мира. При смене режима сбрасываются удерживаемые клавиши. Во время вождения нет верхнего меню: только скорость/состояние машины, краткая подсказка и дисклеймер. Настройки и редактор маршрутов остаются на стартовом экране; пока доступны лишь описания границ прототипа.

Дополнительный ручной smoke **в Standalone Game**:
- [ ] При запуске меню полноэкранное и непрозрачное; курсор виден. W/S/Enter не запускают скрытую машину.
- [ ] Разделы меню кликабельны, Tab/Enter позволяют активировать кнопки; недоступные функции честно описаны.
- [ ] «Начать заезд» скрывает меню, возвращает захват мыши и создаёт холодное состояние.
- [ ] Esc открывает паузу. Позиция/скорость не меняются во время ожидания и нажатия W/S.
- [ ] Esc/«Продолжить» возвращает тот же заезд; мышь снова управляет камерой/рулём, а не кнопками.
- [ ] «Начать заново» даёт холодный старт без дублирования стен/площадки.
- [ ] «Завершить» показывает технический итог, не фиктивную экзаменационную оценку.
- [ ] «На стартовый экран» и «Новый заезд» работают; после десяти циклов нет наложенных меню или залипшего ввода.
- [ ] Stop/Play удаляет старый Slate-экран, не оставляя его в viewport.

Архив с текущими исходниками можно воспроизвести из корня репозитория:
```sh
python3 tools/package-uedev.py
```
Архив — исходники для сборки, не EXE. UE API/Slate и эти переходы ещё требуют проверки в настоящем редакторе.

## Совместимость UE 5.7: первые ошибки сборки

Обе цели `Source/UEDev.Target.cs` и `Source/UEDevEditor.Target.cs` используют `BuildSettingsVersion.V6` по диагностике установленной UE 5.7.4. Это не подтверждение успешной сборки модуля: следующие ошибки следует разбирать по UBT Log.txt. `TargetBuildEnvironment.Unique` для Launcher-установки не включать.

Если UBT сообщает `0xFF is an invalid start of a value`, descriptor повреждён/в неверной кодировке. Заменить `UEDev.uproject` из свежего архива целиком. В архиве он записан ASCII-совместимым UTF-8 без BOM (Unicode в JSON экранирован); не сохранять его как UTF-16. После замены повторное переключение версии не нужно — EngineAssociation уже 5.7.

## 7. Обновление продольной динамики

Обычная клавиатура не измеряет давление: W плавно набирает команду до выбранного уровня. **Ctrl+колесо** задаёт 10–60 %, **Shift+W в D/M** даёт быстрые 100 %. Отпускание газа снимает команду, заслонка закрывается отдельно; Shift без W не держит газ. В HUD видны D1–D6/M1–M6, RPM, фактическая заслонка и давление тормоза. Лимит обычного газа сохраняется на текущую сессию (в том числе после сброса), не на диск.

Переносимые тесты: разгон 0–100 на свободной прямой без UE-стен — **30,50 с обычным газом 60 %**, **10,70 с Shift**; несколько реальных переключений, спад RPM, M-ограничитель/защита, N без связи с мотором, плавный тормоз и регулировка газа. Это расчёт модели, не замер на короткой площадке: её длины для 0–100 недостаточно.

В полном репозитории после `npm ci` можно выполнить:
```sh
node tests/uedev-powertrain-parity.mjs
```
Тест сверяет 2656 значений C++/TS (тяга, RPM, сопротивление, тормоз и самоход) с абсолютным допуском 1e-9. Это не доказательство полного совпадения симуляции или кроссплатформенной побитовой детерминированности.

После пересборки проверить: 20 % против 60 % газа, более поздние переключения под Shift, падение RPM после повышения, удержание M на скорости, выбег N и отпускание/повторное нажатие S. Площадка по-прежнему ограничена стенами; для полного разгона потребуется длинная карта.
