# Архитектура CityDrivingTraining

Подробный технический справочник для разработчиков, ИИ-агентов и языковых моделей: слои, потоки данных, математика и координаты, контракты хранения, навигация по крупным файлам и каталог всех тестов.

---

Жизненный цикл одного кадра и фиксированный шаг `1/60 с`

Главный цикл находится в `src/components/SimulatorView.tsx` (`[SEC:sim-loop]`):

```text

  │
  ├─ 1. Сбор сырого ввода:
  │     клавиатура (keysRef) + независимые опции мыши (руль в режиме free без ЛКМ или hold с перетаскиванием; газ по удержанию ЛКМ >400 мс, всё выключено по умолчанию) + Shift с плавным множителем тяги x1..x2 + SVG-руль + тач-педали + readBrowserGamepad() → readGamepad(); газ и тормоз взаимоисключающие: новая педаль отпускает предыдущую, конфликт сырых источников разрешается в пользу тормоза
  │     Блокировки P/стартера проходят через checkGearChange / checkEngineToggle (src/sim/controls.ts)
  │
  ├─ 2. Аккумулятор времени: acc += min(frameDt, 0.1); пока acc >= FIXED_DT (1/60 с):
  │     ├─ quantizeInput(input)          // руль до 0,1°, педали до 0,001 — ДО физики!
  │     ├─ stepSimulation(state, input, world, grid, calibration, ruleSet, FIXED_DT)
  │     │    ├─ кинематика велосипедной модели + геометрия Аккермана (wheelDegToSteerRad)
  │     │    ├─ тяга 6-ступенчатой АКПП D1–D6 / ручные M1–M6 / engine braking / тормоз / ручник / сопротивление качению
  │     │    ├─ OBB-коллизии через SpatialGrid (10 м, SAT) и пересечение разметки бокса
  │     │    ├─ детекторы: старт без Q/E (вкл. hazard), ремень, фары, откат, скорость,
  │     │    │             светофор + стоп-линия 1.12, пешеход, контрольные точки, удержание в боксе
  │     │    └─ выход: { state: nextState, newEvents }
  │     └─ если запись не closed: recorder.recordTick(input, state, newEvents)
  │
  ├─ 3. Периодическая страховка незавершённого заезда (closed: false) в IndexedDB
  │     и финализация (closed: true) при зачёте упражнения/маршрута или кнопке «Завершить → Разбор»
  │
  └─ 4. Отрисовка:
        ├─ sceneController.render(state, world, isBraking, opts, mirrors)
        │    ├─ основной кадр WebGL
        │    ├─ салонное зеркало 320×96 — каждый 2-й кадр (TD-06, ADR-011)
        │    └─ левое/правое зеркала 320×160 — каждый 3-й кадр в противофазе
        └─ обновление React-снимка HUD с умеренной частотой (без ререндера всего дерева на 60 Гц)
```

## 3. Система координат, знаки и геометрия Аккермана

```text
              +Z (вперёд / север OSM)
                     ▲
                     │   h > 0 (поворот влево, против ЧС)
                     │  ╱
        FL ┌─────────┼─────────┐ FR
           │    водитель (+X)  │
+X (лево) ◄├─────────●─────────┤► −X (право / правый борт / восток OSM)
  (запад)  │  (x, z) сер. базы │
        RL └─────────┼─────────┘ RR
                     │
                    −Z (назад / юг OSM)
```

- **Точка отсчёта автомобиля `(x, z)`:** середина колёсной базы (`wheelbase = 2,65 м`). Геометрический центр кузова смещён вперёд на `(frontOverhang - rearOverhang) / 2 = +0,05 м` (`frontOverhang = 0,88 м`, `rearOverhang = 0,78 м`, полная длина `4,31 м`, ширина `1,80 м`).
- **Единичные векторы кузова при курсе `h` (рад):**
  - вперёд: `f = (sin h, cos h)`
  - влево: `l = (cos h, -sin h)`
  - вправо: `r = (-cos h, sin h)` (используется в `src/maps/route.ts` для постановки на правую полосу).
- **Руль и колёса:**
  - `steerWheelDeg ∈ [-540°, +540°]`: `+` — влево (клавиша `A`, опционально движение мыши влево, стик влево), `−` — вправо (`D`, мышь вправо). Мышиное руление и газ независимы, оба флага выключены по умолчанию и хранятся в `cdt.controls.v1`.
  - `InputState.throttleMultiplier` (опциональное поле для совместимости со старыми реплеями; отсутствие означает `1`) плавно меняется от `1` до `2` при удержании Shift с газом и записывается в каждом RLE-кадре; физика применяет его к тяге ДВС.
  - Предел внутреннего переднего колеса `maxInnerWheelDeg ∈ [33°, 42°]` (шаг `0,5°`, базовый `35°`).
  - Предельный центральный угол велосипедной модели: `δ_max = atan(1 / (cot(α_inner) + T / (2L)))`, где `T = 1,57 м`, `L = 2,65 м`. При `α_inner = 35°`: `δ_max ≈ 30,11°`, внешнее колесо `≈ 26,2°`.
  - При `35°` функция `wheelDegToSteerRad` возвращает константу `CAR.maxSteer` и сохраняет прежний порядок операций с плавающей точкой для побитной совместимости реплеев (`ADR-005`).

## 4. Детерминизм, реплей и `cdt.golden.v1`

Чтобы реплей через месяц дал **в точности ту же конечную позу и те же события**, в `RecordedAttempt` (`src/sim/recorder.ts`) сохраняются все параметры, влияющие на движение:

1. `inputStream: RleInputFrame[]` — RLE-сжатый поток уже квантованного `InputState` (до `36 000` тиков = 10 минут при 60 Гц).
2. `frame.maxInnerWheelDeg` — действовавший предел выворота на каждом блоке; изменение ползунка на ходу открывает новый RLE-блок (`T24`).
3. `calibration: CalibrationConfig` — геометрия боксов и пороги скорости/удержания.
4. `rulesAtRide: RuleSet` — снимок правил на момент заезда (флаг `stopOnImmediateFail` останавливает заезд в физике).
5. `customWorld?: WorldData` — полный снимок мира, если `scenarioId === "custom"` или `world.embedInAttempt === true` (импортированный локальный файл OSM/GeoJSON).
6. `finalPose: { x, z, h }` — числа IEEE-754 без округления; в `DebriefView` и тестах `T10`, `T22`, `T24` проверяется точное равенство.
7. `attemptChecksum()` (`src/sim/golden.ts`) — 32-битный FNV-1a хэш по сценарию, финальной позе, событиям и RLE-потоку (без дат и случайных `id`).

## 5. Контракты локального хранилища и форматов обмена

### 5.1. IndexedDB `cdt-journal` (`src/storage/journalStore.ts`, `src/sim/journal.ts`)

| Object Store | Ключ | Содержимое | Когда читается |
|---|---|---|---|
| `meta` | `id` (`att-...`) | `AttemptMeta`: дата, ученик, сценарий, длительность, дистанция, `finished`, `closed`, события, оценка, `reviews[]`, `finalPose`, `calibration` | Целиком при запуске приложения (до `JOURNAL_LIMIT = 300` записей) |
| `payload` | `id` (`att-...`) | `AttemptPayload`: `trajectory[]`, `inputStream[]`, `customWorld?`, `rulesAtRide?` | По требованию: при открытии попытки в реплее или при выгрузке бэкапа/golden-набора |

- **Вытеснение при переполнении (>300):** сначала удаляются самые старые попытки **без** оценки инструктора (`reviews`), чтобы не терять эталонную выборку сверки (`T19`).
- **Деградация:** если IndexedDB заблокирован (приватное окно, `file://`, политика браузера), хранилище переключается в режим `"memory"` и явно сообщает об этом в UI, не роняя тренажёр.

### 5.2. Каталог маршрутов OSM (`cdt-route-catalog`)

- Отдельная IndexedDB, не смешанная с журналом попыток: object store `routes`, ключ `id`.
- Каждая запись `cdt.route.v1` содержит путь, длину, последовательность контрольных точек, ODbL-метаданные, fingerprint геометрии и полный `CustomScenarioDef` снимок карты.
- Редактор меняет название и задания КТ (инструкцию, радиус, поворотник, требование остановки), удаляет лишние промежуточные точки; финишная КТ всегда требует остановки. Запись каталога и `scenarioSnapshot.checkpoints` обновляются атомарно.
- Fingerprint — FNV-1a 32-bit по канонизированным данным карты; это маркер смены содержимого, не криптографическая подпись.
- При недоступности IndexedDB используется временный fallback в памяти с предупреждением; синхронизации с сервером нет.
- Экспорт каталога: `cdt.routes.v1.json`; отдельный маршрут: `cdt.route.v1`.

### 5.4. Выгружаемые файлы

- **`cdt.golden.v1` (`.json`)** — эталонный набор попыток с FNV-1a checksum, паспортом авто, версией правил и ревью инструкторов (`src/sim/golden.ts`).

## 6. Навигация по крупным файлам (якоря `[SEC:...]`)

Чтобы не читать тысячи строк целиком, ищите нужный раздел командой `grep -n "SEC:" <файл>`:

### `src/components/SimulatorView.tsx` (~1 750 строк)
- `[SEC:sim-storage]` — хранение `cdt.controls.v1` и 2D-canvas fallback при отсутствии WebGL.
- `[SEC:sim-state]` — состояние компонента, мутабельные рефы цикла, раскладка, профиль геймпада.
- `[SEC:sim-actions]` — `setTurnSignal`, `setGear`, `toggleEngine` (через `src/sim/controls.ts`), `resetAttempt`.
- `[SEC:sim-loop]` — создание `SceneController`, цикл `requestAnimationFrame` + аккумулятор `1/60 с`, опрос геймпада, запись и автосохранение.
- `[SEC:sim-keyboard]` — обработка клавиатуры и сброс педалей при `blur`.
- `[SEC:sim-pointer]` — мышь на холсте, физический 3D-селектор Shiftronic (клик/drag/колесо), обзор головы в салоне, SVG-руль, педали и загрузка OSM.
- `[SEC:sim-toolbar]` — переключение сценариев, загрузка карты, «Завершить → Разбор», «Сброс».
- `[SEC:sim-mirrors]` — плавающие окна 3 зеркал (не скрываются по `H`) и экранного руля.
- `[SEC:sim-hud]` — штрафы, знак скорости/светофор/FPS, строка экзаменатора, окно настроек и геймпада, справка, панель камеры.
- `[SEC:sim-cluster]` — приборка, селектор `P/R/N/D`, ручной режим `M1–M6`, кнопки `I/РН/B/L`, педали и подвал ODbL.

### Модули 3D-рендера (`src/render/*`)
- `sceneController.ts` — сцена, OSM-мир, камеры и зеркала; cockpit-камера использует паспортную кадрировку выбранной Kia, инерцию головы, детенты зеркал и raycast по физическому селектору. Внешняя камера переиспользует scratch-векторы; отсечение зданий кэшируется; прогноз Аккермана записывается в постоянные `Float32Array`.
- `cityBuildings.ts` — здания как простые коробочные меши с общей фасадной и отдельной кровельной текстурами из локальных SVG-ассетов; многоярусные деревья и облачное небо.
- `roadTextures.ts` — офлайн PBR-текстуры асфальта и bump, плитки, бордюров, тактильного покрытия, термопластика, стрел, люков, решёток, газона и трафаретов боксов.
- `roadInfra.ts` — геометрия дорог/тротуаров, бордюры, мостовые ограждения, разметка, переходы, знаки, светофоры и уличные объекты по ГОСТ; использует `roadGeometryPoints()` для согласования со скруглением дорог редактора.
- `roadSignTextures.ts` — процедурные текстуры 12 классов знаков с отражающей поверхностью, формами щитов и дополнительными табличками.
- `vehiclesAndPeds.ts` — пять детализированных моделей Kia, интерьер, зеркала, интерактивный рычаг Shiftronic, приборная панель и пешеходы.
- `headLook.ts`, `cockpitFraming.ts` — инерция обзора водителя, три точки внимания и паспортная кадрировка салона для пяти моделей.
- `SceneController.loadWorld()` сохраняет полигоны `lotPolygon`/`boundaryPolygon`, боксы, контрольные точки, текущие камеры и зеркала активной ветки; новые модули заменяют только графические слои, а не весь контроллер.
- `SceneController.getPerfMetrics()` публикует FPS, p95 кадра, draw calls, треугольники, число геометрий/текстур и число видимых/общих зданий. `textureBytesEstimate` и `geometryBytesEstimate` оценивают объём текстур и вершинных/индексных буферов сцены; `gpuResourceBytesEstimate` — их сумма. Это оценка ресурсов сцены, а не точное значение VRAM: она не включает все render targets, shadow maps и накладные расходы драйвера.
- Ручной одноразовый бенчмарк масштабирования зданий: `tests/perf-benchmark.mjs`. Он импортирует 100/400/900 OSM-зданий, прогревает сцену и собирает медианы метрик; запускается отдельно от CI после `npm run build` и установки Playwright.
- Фасад и кровля зданий поставляются как локальные SVG-ассеты и включаются в автономный бандл; текстуры деревьев, неба, дорог и инфраструктуры создаются локально через Canvas/Three.js. CDN и сетевые ассеты не используются. При смене мира освобождаются материалы и текстуры.

## Ограничения скорости на городских дорогах

Скоростной знак задаёт направленный отрезок от стойки к оси полосы и далее по курсу знака. Длина отрезка хранится в метрах (`RoadSignDef.zoneLength`, `SpeedZone.length`), поперечная ширина действия — в `SpeedZone.halfWidth`. Для пользовательских карт ближайшее пересечение вычисляется при сборке мира и сохраняется в `SpeedZone.endDistance`, поэтому геометрия дорожной сети не пересчитывается на каждом тике физики. Ограничение действует только в пределах продольного отрезка и поперечного коридора. Старые пользовательские сценарии с `zoneRadius` совместимы: прежнее значение читается как длина отрезка.


## Пользовательские дороги в редакторе карт

Инструмент «Дорога» собирает осевую линию кликами по карте; Enter или двойной клик завершает черновик, Esc отменяет его. `RoadSegment.width` допускает 1,5–60 м. Необязательный `cornerRadiusM` задаёт квадратичное скругление узлов: исходные контрольные точки сохраняются в JSON, `roundRoadPolyline()` создаёт производную линию для SVG и `buildCustomWorld()`, а `roadGeometryPoints()` передаёт ту же геометрию в 3D. Поля `layer` и `oneway` сохраняют высотный уровень и односторонность дорог OSM; они используются для эстакад, барьерных ограждений, разметки и стрел 1.18. Радиус ограничивается 45 % длины каждого соседнего сегмента, чтобы короткие участки не схлопывались.


## Произвольные границы мира

`src/maps/boundary.ts` содержит чистую геометрию полигональных границ: проверку простоты и площади, шаблоны неквадратных форм, проекцию точек и удержание габаритов автомобиля внутри контура. `CustomScenarioDef.boundaryPolygon` сохраняется в пользовательском сценарии; `WorldData.boundaryPolygon` ограничивает физику, а `lotPolygon` задаёт точную форму асфальтовой площадки.
## Физические зеркала и адаптивная сцена

`src/render/vehiclesAndPeds.ts` содержит геометрию салона, зеркал и физического 3D-селектора. `src/render/sceneController.ts` создаёт отдельные GPU Render Targets для трёх зеркал; в cockpit-режиме материалы зеркал переключаются на их текстуры, а модель водителя скрывается. Камера привязана к матрице кузова и паспортной кадрировке выбранной Kia. ПКМ вращает взгляд с инерцией, ←/→ переводят внимание между зеркалами и дорогой, G временно переводит взгляд на селектор АКПП. Физический рычаг можно выбрать кликом или перетащить по пазу P–R–N–D / M+/M−; колесо мыши над селектором листает положения. BTSI/Shift Lock и ограничения скорости переключения сохраняются в `src/sim/controls.ts`.

При загрузке `WorldData` подложка земли центрируется по `world.bounds` и масштабируется с запасом 900 м; дальность камеры и туман адаптируются к размерам карты. Для больших миров дальность камеры может достигать 2400 м. Ресурсы Render Targets и материалов освобождаются при уничтожении контроллера.

## Расширенный OSM pipeline

- `src/maps/osmXml.ts` разбирает XML-узлы, дороги, отношения multipolygon и `<bounds>` без DOMParser.
- `src/maps/osmDeconflict.ts` содержит геометрию дорожных коридоров и согласование конфликтов дорог, зданий, ограждений, знаков и зон скорости.
- `src/maps/osmLoader.ts` нормализует OSM XML, Overpass JSON и GeoJSON: `oneway=-1`, roundabout, service, lanes/width, мосты/тоннели по `layer`, multipolygon-дома с дворами и WGS84 origin.
- `src/maps/route.ts` строит кандидаты и граф дорожной сети с учётом направления и уровня дороги; узлы/сегменты индексируются пространственно, поиск пути выполняется A*; `cropOsmPackToPolygon()` ограничивает импорт произвольным полигоном.
- `src/maps/routeCatalog.ts` строит сохраняемую запись между двумя точками, валидирует связность и границы, ставит автомобиль в правую полосу, выделяет повороты с сигналами, создаёт КТ и snapshot исходной карты; `reviseExamRouteRecord()` валидирует правки заданий и синхронизирует их со snapshot.
- `src/storage/routeCatalogStore.ts` хранит каталог в IndexedDB `cdt-route-catalog` v2: `routes` содержит отдельные маршруты, `maps` — общие OSM snapshot по fingerprint. При чтении маршрут гидратируется до полной доменной записи; экспорт JSON остаётся автономным. Интерфейс находится в `src/components/RouteCatalogView.tsx`.

Новые поля схемы необязательны. `RoadSegment.cornerRadiusM` остаётся в активной модели; геометрия пользовательских дорог продолжает строиться через `roadGeometryPoints()`. OSM-импорт остаётся офлайн.


### Перемещение контрольных точек маршрута

Редактор сохранённого маршрута показывает отдельную 2D-схему его снимка OSM: дорожные сегменты, линию построенного маршрута и нумерованные маркеры контрольных точек. Маркер можно перетащить мышью или указателем; координаты преобразуются из экранной системы SVG в метрическую систему карты. При сохранении прежняя проверка целостности ограничивает контрольную точку границей сценария и расстоянием не более 20 м от линии маршрута. Обновлённые координаты одновременно записываются в запись каталога и `scenarioSnapshot.checkpoints`; дорожная геометрия и fingerprint карты не меняются.


### Поиск и фильтрация каталога маршрутов

Каталог формирует список названий карт по сохранённым маршрутам и фильтрует записи локально в браузере. Строка поиска проверяет название маршрута, название исходной карты и названия улиц. Дополнительные фильтры выбирают карту-источник, диапазон длины (до 2, 2–5, 5–10 и от 10 км) и число манёвров (0, 1–2, 3–5, от 6). Счётчик показывает количество результатов относительно полного каталога; пустая выдача имеет отдельное сообщение, сброс возвращает полный список. Отдельного нормализованного поля района в модели нет: селектор карты использует сохранённое название карты.


### Общие снимки карт в каталоге маршрутов

IndexedDB `cdt-route-catalog` использует версию схемы 2 и два object store:

- `routes` — геометрия, длина, улицы, манёвры, контрольные точки, метаданные и `mapFingerprint`; небольшие поля снимка, которые могут отличаться между маршрутами (название/описание, стартовая поза, лимит скорости и настройки сценария), хранятся отдельно как `snapshotMeta`.
- `maps` — общий `scenarioSnapshot` с дорожной сетью и инфраструктурой, ключ — `fingerprint`.

При чтении `loadRouteCatalog()` соединяет запись маршрута с общей картой и накладывает маршрутные поля, возвращая прежний полный `ExamRouteRecord`. Поэтому редактор, запуск и экспорт JSON не зависят от внутренней нормализованной схемы. Импорт старого `cdt.routes.v1` остаётся совместимым: `saveRouteRecord()` сохраняет snapshot отдельно.

При обновлении базы с v1 до v2 курсор upgrade-транзакции переносит snapshot каждой старой записи в `maps`, сохраняет её маршрутные поля и удаляет дублирующее поле из `routes`. Удаление записи проверяет оставшиеся ссылки и удаляет общую карту только при отсутствии других маршрутов с тем же fingerprint.
