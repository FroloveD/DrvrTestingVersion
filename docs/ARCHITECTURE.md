# Архитектура CityDrivingTraining

Подробный технический справочник для разработчиков, ИИ-агентов и языковых моделей: слои, потоки данных, математика и координаты, контракты хранения, навигация по крупным файлам и каталог всех тестов.

---

## 1. Слои и границы зависимостей

Проект жёстко разделён на **чистое детерминированное ядро** (исполняется в любом JS-рантайме, включая Node.js без DOM и WebGL) и **браузерную оболочку** (React + Three.js + Web APIs).

               │                          │
               ▼                          ▼

## 2. Жизненный цикл одного кадра и фиксированный шаг `1/60 с`

Главный цикл находится в `src/components/SimulatorView.tsx` (`[SEC:sim-loop]`):

```text
requestAnimationFrame(now)
  │
  ├─ 1. Сбор сырого ввода:
  │     клавиатура (keysRef) + мышь/SVG-руль + тач-педали + readBrowserGamepad() → readGamepad()
  │     Блокировки P/стартера проходят через checkGearChange / checkEngineToggle (src/sim/controls.ts)
  │
  ├─ 2. Аккумулятор времени: acc += min(frameDt, 0.1); пока acc >= FIXED_DT (1/60 с):
  │     ├─ quantizeInput(input)          // руль до 0,1°, педали до 0,001 — ДО физики!
  │     ├─ stepSimulation(state, input, world, grid, calibration, ruleSet, FIXED_DT)
  │     │    ├─ кинематика велосипедной модели + геометрия Аккермана (wheelDegToSteerRad)
  │     │    ├─ тяга 5-ст. АКПП / тормоз / ручник / сопротивление качению
  │     │    ├─ OBB-коллизии через SpatialGrid (10 м, SAT) и пересечение разметки бокса
  │     │    ├─ детекторы: старт без Q/E (вкл. hazard), ремень, фары, откат, скорость,
  │     │    │             светофор + стоп-линия 1.12, пешеход, контрольные точки, удержание в боксе
  │     │    └─ выход: { state: nextState, newEvents }
  │     └─ если запись не closed: recorder.recordTick(input, state, newEvents)
  │
  ├─ 3. Периодическая страховка незавершённого заезда (closed: false) в IndexedDB
  │     и финализация (closed: true) при зачёте упражнения/маршрута или кнопке «Завершить → Разбор»
  │
  └─ 4. Отрисовка:
        ├─ sceneController.render(state, world, isBraking, opts, mirrors)
        │    ├─ основной кадр WebGL
        │    ├─ салонное зеркало 320×96 — каждый 2-й кадр (TD-06, ADR-011)
        │    └─ левое/правое зеркала 320×160 — каждый 3-й кадр в противофазе
        └─ обновление React-снимка HUD с умеренной частотой (без ререндера всего дерева на 60 Гц)
```

## 3. Система координат, знаки и геометрия Аккермана

```text
              +Z (вперёд / север OSM)
                     ▲
                     │   h > 0 (поворот влево, против ЧС)
                     │  ╱
        FL ┌─────────┼─────────┐ FR
           │    водитель (+X)  │
+X (лево) ◄├─────────●─────────┤► −X (право / правый борт / восток OSM)
  (запад)  │  (x, z) сер. базы │
        RL └─────────┼─────────┘ RR
                     │
                    −Z (назад / юг OSM)
```

- **Точка отсчёта автомобиля `(x, z)`:** середина колёсной базы (`wheelbase = 2,65 м`). Геометрический центр кузова смещён вперёд на `(frontOverhang - rearOverhang) / 2 = +0,05 м` (`frontOverhang = 0,88 м`, `rearOverhang = 0,78 м`, полная длина `4,31 м`, ширина `1,80 м`).
- **Единичные векторы кузова при курсе `h` (рад):**
  - вперёд: `f = (sin h, cos h)`
  - влево: `l = (cos h, -sin h)`
  - вправо: `r = (-cos h, sin h)` (используется в `src/maps/route.ts` для постановки на правую полосу).
- **Руль и колёса:**
  - `steerWheelDeg ∈ [-540°, +540°]`: `+` — влево (клавиша `A`, движение мыши влево, стик влево), `−` — вправо (`D`, мышь вправо).
  - Предел внутреннего переднего колеса `maxInnerWheelDeg ∈ [33°, 42°]` (шаг `0,5°`, базовый `35°`).
  - Предельный центральный угол велосипедной модели: `δ_max = atan(1 / (cot(α_inner) + T / (2L)))`, где `T = 1,57 м`, `L = 2,65 м`. При `α_inner = 35°`: `δ_max ≈ 30,11°`, внешнее колесо `≈ 26,2°`.
  - При `35°` функция `wheelDegToSteerRad` возвращает константу `CAR.maxSteer` и сохраняет прежний порядок операций с плавающей точкой для побитной совместимости реплеев (`ADR-005`).

## 4. Детерминизм, реплей и `cdt.golden.v1`

Чтобы реплей через месяц дал **в точности ту же конечную позу и те же события**, в `RecordedAttempt` (`src/sim/recorder.ts`) сохраняются все параметры, влияющие на движение:

1. `inputStream: RleInputFrame[]` — RLE-сжатый поток уже квантованного `InputState` (до `36 000` тиков = 10 минут при 60 Гц).
2. `frame.maxInnerWheelDeg` — действовавший предел выворота на каждом блоке; изменение ползунка на ходу открывает новый RLE-блок (`T24`).
3. `calibration: CalibrationConfig` — геометрия боксов и пороги скорости/удержания.
4. `rulesAtRide: RuleSet` — снимок правил на момент заезда (флаг `stopOnImmediateFail` останавливает заезд в физике).
5. `customWorld?: WorldData` — полный снимок мира, если `scenarioId === "custom"` или `world.embedInAttempt === true` (импортированный локальный файл OSM/GeoJSON).
6. `finalPose: { x, z, h }` — числа IEEE-754 без округления; в `DebriefView` и тестах `T10`, `T22`, `T24` проверяется точное равенство.
7. `attemptChecksum()` (`src/sim/golden.ts`) — 32-битный FNV-1a хэш по сценарию, финальной позе, событиям и RLE-потоку (без дат и случайных `id`).

## 5. Контракты локального хранилища и форматов обмена

### 5.1. IndexedDB `cdt-journal` (`src/storage/journalStore.ts`, `src/sim/journal.ts`)

| Object Store | Ключ | Содержимое | Когда читается |
|---|---|---|---|
| `meta` | `id` (`att-...`) | `AttemptMeta`: дата, ученик, сценарий, длительность, дистанция, `finished`, `closed`, события, оценка, `reviews[]`, `finalPose`, `calibration` | Целиком при запуске приложения (до `JOURNAL_LIMIT = 300` записей) |
| `payload` | `id` (`att-...`) | `AttemptPayload`: `trajectory[]`, `inputStream[]`, `customWorld?`, `rulesAtRide?` | По требованию: при открытии попытки в реплее или при выгрузке бэкапа/golden-набора |

- **Вытеснение при переполнении (>300):** сначала удаляются самые старые попытки **без** оценки инструктора (`reviews`), чтобы не терять эталонную выборку сверки (`T19`).
- **Деградация:** если IndexedDB заблокирован (приватное окно, `file://`, политика браузера), хранилище переключается в режим `"memory"` и явно сообщает об этом в UI, не роняя тренажёр.

### 5.1.1. IndexedDB `cdt-audio` (`src/audio/trackStore.ts`) — кэш сохранённых треков ШГУ

| Object Store | Ключ | Содержимое | Когда читается |
|---|---|---|---|
| `tracks` | `key` (`radio:<станция>:<сек>s`) | `SavedTrack`: станция, частота, длительность, дата и `blob` — WAV-трек, отрендеренный `renderTrackWav` | Список — при открытии панели «Управление»; сам трек — при выборе «Слушать кэш» |

- **Живой эфир:** реальные интернет-станции (`INTERNET_RADIO_STATIONS`) играют через `<audio>` по https-потоку; при недоступности сети ШГУ честно показывает «ЭФИР НЕДОСТУПЕН», а сохранённые треки продолжают играть офлайн.
- **Сохранение во время поездки:** кнопка «⤓ Сохранить трек в поездке» детерминированно рендерит 32-секундный эфирный трек в WAV (`renderTrackWav`) и кладёт его в IndexedDB, поэтому на него не влияет ни загрузка ЦП, ни реплей.

### 5.3. Выгружаемые файлы

- **`cdt.golden.v1` (`.json`)** — эталонный набор попыток с FNV-1a checksum, паспортом авто, версией правил и ревью инструкторов (`src/sim/golden.ts`).
- **`cdt.backup.v1` (`.json`)** — полная резервная копия всех попыток, правил, калибровки, своего сценария и заметки о лицензии (`src/components/PrivacyLegalView.tsx`).
- **CSV отчёт (`.csv`)** — UTF-8 с BOM и разделителем `;` для прямого открытия в русскоязычном Excel (`src/analytics/summary.ts`).
- **Свой сценарий (`.json`)** — описание площадки/маршрута с валидацией через `validateCustomScenario` (`src/scenarios/custom.ts`).
- **`HANDOFF.md` / `strategy.md` / `cdt-report-YYYY-MM-DD.md`** — текстовые выгрузки через `downloadText` (`src/components/Icons.tsx`, `analyticsToMarkdown` в `src/analytics/summary.ts`).

## 6. Навигация по крупным файлам (якоря `[SEC:...]`)

Чтобы не читать тысячи строк целиком, ищите нужный раздел командой `grep -n "SEC:" <файл>`:

### `src/components/SimulatorView.tsx` (~1 750 строк)
- `[SEC:sim-storage]` — хранение `cdt.controls.v1` и 2D-canvas fallback при отсутствии WebGL.
- `[SEC:sim-state]` — состояние компонента, мутабельные рефы цикла, раскладка, профиль геймпада.
- `[SEC:sim-actions]` — `setTurnSignal`, `setGear`, `toggleEngine` (через `src/sim/controls.ts`), `resetAttempt`.
- `[SEC:sim-loop]` — создание `SceneController`, цикл `requestAnimationFrame` + аккумулятор `1/60 с`, опрос геймпада, запись и автосохранение.
- `[SEC:sim-keyboard]` — обработка клавиатуры и сброс педалей при `blur`.
- `[SEC:sim-pointer]` — мышь на холсте, вращение SVG-руля, раздельные педали с привязкой `pointerId`, загрузка OSM.
- `[SEC:sim-toolbar]` — переключение сценариев, загрузка карты, «Завершить → Разбор», «Сброс».
- `[SEC:sim-mirrors]` — плавающие окна 3 зеркал (не скрываются по `H`) и экранного руля.
- `[SEC:sim-hud]` — штрафы, знак скорости/светофор/FPS, строка экзаменатора, окно настроек и геймпада, справка, панель камеры.
- `[SEC:sim-cluster]` — приборка, селектор `P/R/N/D`, кнопки `I/РН/B/L`, педали газа/тормоза и подвал ODbL.

### `src/render/sceneController.ts` (~1 430 строк)
- `[SEC:render-textures]` — процедурные текстуры неба, асфальта, контактной тени, окон, знака «У», знаков скорости и номеров боксов.
- `[SEC:render-car]` — колёса и процедурный кузов Kia Ceed JD с полым салоном, оптикой и отдельным слоем зеркал (`OWN_MIRROR_HARDWARE_LAYER`).
- `[SEC:render-init]` — конструктор `SceneController`, освещение, render targets (`rearRT` `320×96`, `sideRT` `320×160`), орбита, пресеты качества.
- `[SEC:render-world]` — `loadWorld`, препятствия, припаркованные машины, разметка, здания, светофоры, переходы, контрольные точки.
- `[SEC:render-frame]` — `render`, `renderInto` (зеркала без аллокаций на кадр, троттлинг `TD-06`), `updateCamera` (водительская, преследующая, сверху, орбитальная).
- `[SEC:render-dispose]` — метрики FPS/зданий и полное освобождение GPU-памяти.

### `src/components/DebriefView.tsx` (~905 строк) и `src/components/CustomScenarioView.tsx` (~840 строк)
- `DebriefView.tsx`: `[SEC:debrief-review]` · `[SEC:debrief-state]` · `[SEC:debrief-map]` · `[SEC:debrief-journal]`.
- `CustomScenarioView.tsx`: `[SEC:custom-fields]` · `[SEC:custom-forms]` · `[SEC:custom-preview]`.

## UEDev — изолированный нативный эксперимент

Проект `ue/UEDev/UEDev.uproject` (UE 5.7) не подключён к Vite и не меняет браузерное ядро.
- `ue/UEDev/Source/UEDev/Public/DrivingModel.h` — переносимый C++-стенд плоской кинематики, не полный порт TS; тест `ue/UEDev/Tests/DrivingModelTest.cpp`.
- `ue/UEDev/Source/UEDev/Public/UEDevPawn.h` и `Private/UEDevPawn.cpp` — ввод клавиатуры/мыши, аккумулятор 1/60, sweep корпуса, камера.
- `ue/UEDev/Source/UEDev/Public/UEDevGameMode.h` и `Private/UEDevGameMode.cpp` — процедурная площадка и диагностический HUD.
- `ue/UEDev/Source/UEDev/Private/UEDev.cpp` — регистрация runtime-модуля; `.Target.cs` / `.Build.cs` — конфигурация сборки.

Граница координат: ядро в метрах (+z вперёд, +x влево, heading влево), UE в сантиметрах (X=z×100, Y=−x×100, yaw=−heading). Обратное преобразование позиции при sweep-столкновении сохраняет согласованность ядра и актора. Физика Chaos Vehicles, сопоставимый реплей и оценка пока не подключены. Отдельный CI проверяет только переносимое C++-ядро, не Unreal SDK. Начальный план и проверка руками: `ue/PLAN.md`, `ue/README.md`.

### UEDev: стартовое меню без переноса веб-оболочки

`ue/UEDev/Source/UEDev/Public/SessionFlow.h` — переносимый автомат Menu/Driving/Paused/Summary (тот же C++-тест). `ue/UEDev/Source/UEDev/Public/UEDevPlayerController.h` и `Private/UEDevPlayerController.cpp` — Slate-меню, переходы, фокус и курсор. Только Driving включает Tick/Input машины; GameMode назначает контроллер, HUD скрыт вне Driving. Площадка остаётся в одном мире. Разделы маршрутов/настроек/журнала выделены на стартовом экране, но их содержимое ещё не портировано. `tools/package-uedev.py` собирает архив исходников с документацией, исключая кэши/бинарные файлы сборки.

### UEDev: продольная динамика и регулируемый цифровой газ

`ue/UEDev/Source/UEDev/Public/Powertrain.h` — перенос тяги по 6 ступеням, момента/RPM, сопротивлений, гидротрансформаторного самохода и рабочего тормоза из `src/sim/vehicle.ts`. DrivingModel теперь сглаживает заслонку/давление, переключает D с гистерезисом и размыканием тяги, рассчитывает RPM, ограничивает M. `tests/uedev-powertrain-parity.mjs` сравнивает 2656 значений функций TS/C++ с допуском 1e-9; DrivingModelTest дополнительно проверяет интегрированный разгон, переключения, M/N, газ и гидравлику. Ни боковая динамика, ни сцена/коллизии не объявляются полностью эквивалентными вебу. Ctrl+колесо в Pawn регулирует обычный газ 10–60 %, иначе колесо меняет зум; Shift+W в D/M — 100 %. HUD выводит ступень, RPM, заслонку и давление тормоза. Веб-управление не изменено.

### UEDev: маршрут и настройки стартового экрана

`ue/UEDev/Source/UEDev/Public/RouteRun.h` — два технических маршрута (площадка и километровая прямая), последовательные КТ с swept-проверкой, остановка на финальной КТ, время/дистанция/максимальная скорость; нормализация уровня газа. Это не новые правила экзамена. Pawn сбрасывается на старт активного маршрута и считает прогресс на фиксированных шагах после sweep. GameMode при старте перестраивает геометрию, удаляя собственные прежние акторы. PlayerController сохраняет выбранный маршрут и газ через GConfig/GameUserSettings.ini, строит меню со слайдером и хранит до десяти технических итогов только в памяти. HUD показывает прогресс. Тесты RouteRun включены в DrivingModelTest.cpp; сохранение/Slate/геометрия требуют проверки в UE.

### Визуальный слой UEDev: модели и свет

Вместо куба используется сборная low-poly модель: кузов, кабина, непрозрачные тёмные окна, четыре статичных колеса, бамперы и цветные вставки фар. Это условный автомобиль, не точная модель Kia и не салон. Детали сделаны из Engine/BasicShapes; цвет задаётся параметром Color динамических материалов. Единственная коллизия — прежний Body, физика не менялась. Фары пока не светят, колёса не анимированы.

Площадка получила тёмное покрытие, визуальную прерывистую ось и краевые полосы, конусы вместо кубических маркеров. Разметка — ориентир технической сцены, не утверждённая схема дорожного движения. Свет: один динамический солнечный источник, SkyAtmosphere и SkyLight; без внешних текстур, bake и Lumen. При смене маршрута свет не дублируется. Поведение не проверено в UE SDK.

Ручная проверка после пересборки UE: видны кузов/окна/колёса и разные цвета; колёса у поверхности; небо не чёрное, затенённая сторона читается; разметка не мерцает; после трёх смен маршрута нет остатков моделей; коллизии и управление прежние. Если используемый Engine-материал не имеет параметра Color, детали останутся стандартного цвета — проверить в UE 5.7.

### UEDev: материалы и автомобильный свет
Pawn и GameMode явно назначают Engine/BasicShapes/BasicShapeMaterial перед созданием MID, не наследуя шахматный материал мешей. `uedev::Lights(State, headlights)` в DrivingModel — чистая производная состояния (выключатель L → фары, давление тормоза → стопы, ДВС+R → задний ход), без мутации физики. Pawn создаёт SpotLight-компоненты один раз в конструкторе и обновляет видимость после шага, сброса и дискретных действий; пауза сохраняет состояние. Свет без теней, цвет задней вставки меняется отдельно, без эмиссии. Новых клавиш, оценки и полного переноса веб-освещения нет. Логика проверена DrivingModelTest, рендер требует UE.

UEDev: PrepareDrive — отдельная атомарная операция подготовки, не Reset. Сохраняет позу/динамические счётчики и не касается RouteRun. Только P/N/D при |v|≤0,35; P требует тормоз. Pawn Ready вызывает её без Reset/Accumulator. Независимый флаг фар меняется L, холодный Reset выключает его. Тесты: DrivingModelTest (отказ без частичной мутации, поза/руль, движение, R, N, независимость фар).

### UEDev: HUD по группировке v1

`ue/UEDev/Source/UEDev/Public/HudModel.h` — чистая презентационная модель: приоритет следующего действия, дистанция до границы текущей КТ, масштаб viewport. Не меняет State/RouteRun, без оценки. Проверяется DrivingModelTest (все подсказки, завершение/граница зоны, размеры экранов).

`ue/UEDev/Source/UEDev/Private/UEDevHUD.cpp` — отдельный Canvas-адаптер AUEDevHUD вместо диагностических строк в GameMode. Приборы: крупная скорость/RPM с порогами v1 4400/5500/6500, селектор и четыре состояния, две шкалы фактической заслонки/давления, КТ и статистика, следующая подсказка. Координаты масштабируются от 1280×720 и закреплены по краям. Pawn H вызывает AHUD::ShowHUD; дисклеймер остаётся, физика/курсор не меняются. Состояние фар читается отдельным getter, а не выводится из ДВС. Нет ложных индикаторов неперенесённых систем/экзаменационных штрафов, кликабельности и drag; это информационный перенос, не полный UI-паритет.
