### 2.2. `Arena_v1` / `Arena_v2` (`v0.3`) vs `main` (`v0.2`) — масштабный скачок (`+6 873 / −2 417` строк, 48 файлов)

Что появилось и улучшилось в `Arena_v1`/`Arena_v2` по сравнению с `main`:

1. **Настраиваемый выворот колёс `33–42°` (`src/sim/vehicle.ts`, `SteeringLimitControl.tsx`):**
   - `WHEEL_LOCK` (`min: 33`, `max: 42`, `defaultDeg: 35`, `step: 0.5`), `normalizeWheelLock()`, `centralSteerLimit()`.
   - При `35°` математика совпадает побитно со старыми записями; действующий угол пишется в каждый RLE-блок (`RleInputFrame.maxInnerWheelDeg`) и применяется на реплее; изменение угла не пересоздаёт мир (`ScenarioGeometry`) и не сбрасывает заезд.
2. **Точный детерминизм реплея (`src/sim/recorder.ts`):**
   - `quantizeInput()` вызывается до `stepSimulation()` (ранее округление после шага давало дрейф реплея на аналоговом вводе).
   - `finalPose` хранится без округления `.toFixed()`, сохраняется `rulesAtRide` (важно для `stopOnImmediateFail`) и `customWorld` для импортированных карт OSM (`embedInAttempt: true`).
3. **Журнал в IndexedDB (`src/sim/journal.ts`, `src/storage/journalStore.ts`):**
   - База `cdt-journal` с раздельными хранилищами `meta` (лёгкий список до 300 попыток) и `payload` (тяжёлый RLE-поток, траектория, мир, правила).
   - Автоперенос старого `localStorage`-ключа `cdt.attempts.journal.v1`, fallback в память при недоступности IndexedDB, постоянный `AttemptRecorder.id`, автосохранение незавершённого заезда и признак `closed`.
4. **Статистика учеников и калибровка с инструктором (`src/analytics/*`, `AnalyticsView.tsx`, `DebriefView.tsx`):**
   - Заменили `src/stats/report.ts` + `ReportsView.tsx`.
   - Привязка заездов к ученикам (демо-заезды отделены в `«Демо (синтетика)»`), независимые оценки нескольких инструкторов (`InstructorReview`), слепой режим (`cdt.blindReview.v1`), расчёт согласия с доверительным интервалом Уилсона (порог `90%`, минимум `20` оценок), список расхождений, выгрузка CSV и `cdt.golden.v1`.
5. **Новый адаптер USB-руля и педалей (`src/input/gamepad.ts`, `browserGamepads.ts`, `GamepadPanel.tsx`):**
   - Устройства выключены по умолчанию; вместо угадывания профилей G29 — пошаговая калибровка (`startCalibration` / `advanceCalibration`), защита осей `AxisArming` (исключает ложные 50% газа в покое), санитизация профиля.
6. **Маршрут по реальной геометрии OSM (`src/maps/route.ts`, `osmLoader.ts`, `catalog.ts`):**

7. **3D-зеркала и HUD (`sceneController.ts`, `FloatingPanel.tsx`, `SimulatorView.tsx`):**
   - Раздельные render targets и пропорции зеркал (заднее `320×96`, боковые `320×160`) без перетекания строк и лишних аллокаций.
   - Перемещение панелей за grip или долгим нажатием `420 мс`; у педалей grip отделён от рабочей области (мультитач безопасен); тренажёр остаётся смонтированным при смене вкладки.
8. **Правовой блок и стратегия (`PrivacyLegalView.tsx`, `src/strategy/plan.ts`, `StrategyView.tsx`):**

## 4. Целевая архитектура документации (для людей, агентов и LLM)

Принцип: **у каждого документа ровно одна роль, факты не дублируются вручную, ключевые утверждения проверяются скриптом**.

```text
/
├── README.md                 # Человеку: что за проект, статус unvalidated, быстрый старт, карта репо и веток
├── AGENTS.md                 # ИИ-агентам (автоподхват): 16 инвариантов, запреты, обязательный гейт, правила коммитов
├── HANDOFF.md                # Автогенерация из src/handoff.ts: полный контекст сессии (синхронен с UI)
├── WORKLOG.md                # Живой пульс ветки: статус, на чём остановились, план шагов, реестр техдолга TD-*
├── NOTICE                    # Правовой статус, ODbL 1.0, лицензии зависимостей
└── docs/
    ├── ARCHITECTURE.md       # Слои, цикл кадра 1/60 с, система координат, схемы хранилища, оглавление больших файлов
    ├── ADR.md                # Журнал архитектурных решений (ADR-001…): контекст → решение → последствия
    ├── BRANCH_AUDIT.md       # Этот документ: сравнение веток, аудит и история консолидации
    └── CALIBRATION_GUIDE.md  # Инструктору автошколы (без кода): как провести слепую сверку и подписать правила
```

### Стандарты внутри кода
1. **Паспорт модуля** в шапке каждого файла `src/**` (5–8 строк): назначение, слой (`pure-core` / `input` / `three-render` / `ui`), ключевые инварианты, покрывающие тесты (`T01…T24` / смоук `A…N`).
2. **Секционные якоря** `// === [SEC:имя] Описание ===` в файлах >400 строк (`SimulatorView.tsx`, `sceneController.ts`, `DebriefView.tsx`, `CustomScenarioView.tsx`) с оглавлением в шапке файла.
3. **JSDoc на публичных типах и функциях ядра** с единицами измерения (`м`, `м/с`, `км/ч`, `рад`, `°`, `с`) и знаками осей (`+Z` вперёд, `+X` влево, `+h` влево).
4. **Автоматический гейт документации** в `scripts/run-tests.mjs` и CI: проверка чистоты всех 7 каталогов ядра, прогон `runAllSelfTests()`, сверка `HANDOFF.md` с `src/handoff.ts`, проверка существования всех путей из карты модулей, проверка секционных якорей `[SEC:...]` и автономности `dist/index.html`.
