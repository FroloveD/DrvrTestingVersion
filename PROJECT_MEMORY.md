## 2. Что представляет собой продукт

Самодостаточное одностраничное приложение на React + TypeScript + Three.js. Производственная сборка — один автономный `dist/index.html`; рантайм не должен зависеть от CDN или внешних сетевых запросов. Данные учеников и настройки по умолчанию остаются локально в браузере (IndexedDB/localStorage).

Основные подсистемы:
- 3D-тренажёр и детерминированная физика автомобиля с фиксированным шагом 1/60 с.
- Сценарии площадки и города, собственный редактор карт и офлайн-импорт OSM XML / Overpass JSON / GeoJSON.
- Построение, редактирование, хранение и повторное открытие экзаменационных маршрутов на OSM-графе (oneway/layer, A*).
- HUD, зеркала, салон, приборная панель, камеры, органы управления и селектор АКПП.
- Автопарк из пяти моделей Kia: Picanto TA, Rio FB, Ceed JD, XCeed CD, Sorento MQ4.
- Клавиатура, мышь, мультитач-педали, USB-руль/геймпад, редактор раскладки.
- Журнал попыток, детерминированный реплей, оценка, слепая проверка инструктором и статистика.
- FM-каталог, WebAudio-звук, офлайн WAV-кэш и экран ШГУ.

Это учебная симуляция, а не официальный экзамен ГИБДД. Профиль оценки и размеры боксов остаются `unvalidated`, пока не пройдут сверку и подпись инструктора.

- React 19.2, TypeScript 5.9, Vite 7.3, Tailwind CSS 4.1, Three.js 0.187.

## 4. Непреложные правила разработки

1. Перед любой правкой прочитать `AGENTS.md`, актуальные записи `WORKLOG.md` и `HANDOFF.md`; для физики, рендера и хранения — соответствующие разделы `docs/ARCHITECTURE.md` и `docs/ADR.md`.
2. Работать непосредственно в `arena/exam-routes-v1-integration`, пока владелец явно не изменит решение.
3. Делать небольшие целевые изменения; не переписывать соседние подсистемы без необходимости.
4. После каждого законченного шага обновлять `WORKLOG.md`; если меняется передача контекста — поддерживать генератор `src/handoff.ts` и пересобирать `HANDOFF.md` командой `node scripts/write-handoff.mjs`.
5. Не менять `package.json` и `vite.config.ts` вручную без отдельной необходимости/согласования, указанного в `AGENTS.md`.
6. Чистые каталоги `src/sim`, `src/scoring`, `src/maps`, `src/scenarios`, `src/analytics`, `src/storage`, `src/strategy` не должны импортировать Three.js или обращаться к `window` / `document`.
7. Не добавлять CDN, обязательные сетевые зависимости или сетевую загрузку карт в рантайме. Импорт карт — локальный.
8. Сохранять детерминизм симуляции и реплея, обратную совместимость сохранённых данных и пользовательских настроек.
9. Не ослаблять проверки Browser Smoke ради зелёного CI: исправлять причину, а не обходить assertion.
10. Не объявлять CI, Deploy или браузерную проверку успешными без подтверждения именно для текущего HEAD.
11. Не выдавать оценку тренажёра за норматив ГИБДД; `unvalidated` снимается только после калибровки и подписи инструктора.
12. Не выполнять необратимые Git-операции (force push, hard reset, массовое удаление, слияние расходящихся веток) без предварительного анализа и безопасного плана.

## 5. Ключевые технические контракты

- Координаты: +Z вперёд/север OSM, +X левый борт, −X правый; положительный heading — поворот влево.
- Физика: фиксированный шаг 1/60 с; рендер интерполирует, физика нет.
- Педали взаимоисключающие; тормоз имеет приоритет при конфликте сырых источников; в D торможение не вызывает реверс.
- АКПП P/R/N/D и ручной режим M1–M6; действуют BTSI/Shift Lock и ограничения включения P/R на скорости.
- Холодный старт: двигатель выключен, P, ручник затянут, ремень снят.
- OSM-данные требуют атрибуции © OpenStreetMap contributors и соблюдения ODbL 1.0.
- Каталог маршрутов использует IndexedDB `cdt-route-catalog` v2: `routes` содержит маршруты, `maps` — общие snapshots карты по fingerprint; предусмотрена миграция v1 → v2.
- Офлайн WAV радио — синтезированный фрагмент по параметрам станции, а не запись её живого эфира. Импорт реальных аудиофайлов — отдельная задача с проверкой лицензии, доступности сохранения и квоты хранилища.

### Реализовано / добавлено в текущем цикле
- Ветка `arena/exam-routes-v1-integration` содержит интеграцию выбранных функций из Arena_v1: редактор переназначения клавиш, процедурный WebAudio-звук двигателя, FM-каталог/радио и офлайн WAV, живые приборы и ШГУ, выбор автомобиля и FM-станций в сценарии.
- Каталог маршрутов OSM и его редактор: сохранение, повторное открытие, редактирование контрольных точек, экспорт/импорт и локальные snapshots.
- IndexedDB route catalog v2 с миграцией из v1; общий snapshot карты хранится отдельно от записей маршрутов.
- В `snapshotMeta` сохраняются индивидуальные `playerCarId` и `radioStationIds`, чтобы несколько маршрутов одной карты не перезаписывали настройки друг друга.
- Browser Smoke P расширен сценариями миграции v1→v2, сохранения общей карты при удалении одного маршрута, очистки последнего неиспользуемого snapshot и восстановления индивидуальных настроек.
- Browser Smoke Q покрывает изоляцию меню HUD и порядок z-index плавающих панелей. Последняя тестовая корректировка Q8 переносит клик с кнопочной области заголовка на свободную область текста (`x=70`) и ожидает обновления React z-index; production HUD не менялся, assertion не ослаблялся.
- OSM-маршрутизатор учитывает длинные легальные односторонние объезды без искусственного ограничения стоимости A*; T32 покрывает объезд более 2,5 км, T46 — импорт `bridge`/`tunnel`, сохранение `layer` и стык рампы.
- На реальной выгрузке Тюмени выявлена и исправлена семантика `tunnel=building_passage`: наземные проезды остаются на `layer=0`; полный XML → WorldData путь покрыт T46.
- Первичный топологический аудит исходного OSM JSON: 952 автомобильных highway-way, 0 отсутствующих ссылочных node ID, 10 компонент по общим OSM node ID (две крупные: 833 и 96 ways). Радиусные объединения и T-примыкания по текущим допускам не изменили компоненты. Это не признано дефектом без географической проверки; явных автомобильных bridge/tunnel в выгрузке нет.
- В XML/Overpass JSON и GeoJSON импорте устранён общий лимит 650 зданий; T47 проверяет импорт 651 здания без потери объектов. Исходные OSM footprint/inner rings уже рендерятся через ExtrudeGeometry отдельно от collision OBB; исправлено дальнее отсечение spatial footprint-батчей и capacity резервного InstancedMesh. T48 проверяет multipolygon, внутренний двор, roof:shape и roof:height в данных. Roof:shape пока не формирует отдельную 3D-геометрию крыши — поверхность остаётся плоской. При ошибке merge footprint-ячеек объекты не помечаются отрисованными и остаются на резервном OBB/InstancedMesh пути. T47/T48 и полный gate локально ещё не подтверждены.
- `src/handoff.ts` и генерируемый `HANDOFF.md` синхронизированы с актуальным набором Browser Smoke A–S.

## 7. Ближайшие действия

1. При начале новой сессии проверить актуальный HEAD активной ветки и статусы CI/Deploy; не полагаться на статусы из этого файла.
2. Завершить проверку Browser Smoke A–S после исправления Q8; при падении исследовать первопричину, не ослабляя assertions.
3. После зелёного CI/Deploy проверить опубликованную сборку и критические пользовательские сценарии.
4. Продолжить технический аудит OSM: визуально проверить две крупные компоненты выгрузки Тюмени на карте и сопоставить их с географическими барьерами/границами экспорта; получить реальный датасет с автомобильными мостом, тоннелем и рампой; затем проверить сложные перекрёстки и обрезку карты.
5. Для каждого законченного изменения обновлять `WORKLOG.md`; `HANDOFF.md` генерировать из `src/handoff.ts`, когда меняется карта модулей или передаваемая техническая документация.
6. Не тратить время на повторное слияние `final` → `integration`: PR #10 уже слит, ветка `final` полностью включена.
